# 企業検索・架電の改善（未公開）

2026-10-05。既存V1からの追加開発。新規サービス・APIキー・外部連携は不要。本番変更・push・公開は未実施。

## 利用者向けの変更

- 企業一覧と企業選択の検索対象を、会社名・電話番号・法人番号に拡張。電話番号は全角数字、ハイフン、括弧、空白の違いを吸収する。保存済みの電話番号そのものは変更しない。
- 担当者選択は名前・電話番号・メールアドレスで検索できる。企業の指定条件を維持する。
- 候補選択に20件単位のページ送りを追加。同名の候補も、企業は所在地・電話・法人番号、担当者は部署・役職・電話・メールを見て選べる。選択後にも補足情報を表示する。
- 企業一覧の「架電を記録」から、対象企業名・電話番号を確認して既存の活動フォームへ進める。通常の保存では一覧に留まり、活動と最終接触の表示を再取得する。「保存して次の企業へ」は従来の会社名順の動作を維持する。
- 一覧の電話番号を電話アプリで開くリンクにし、詳細画面と共に全角数字を正しく扱う。自動架電やZoom Phone API接続は行わない。

## 実装・DB変更

`20261005045823_company_contact_search.sql` は `company_search` と `contact_search` の検索用ビューを追加する。両方とも `security_invoker=true`。企業の既存集計ビューもinvokerのままで、基になるテーブルの組織・失効セッションRLSを維持する。anon/PUBLICの権限は取り消し、authenticatedにはSELECTだけを許可。データを書き換えず、既存書き込みAPIも維持する。

電話の検索用列は読み取り時に数字に正規化する。数値/電話番号らしい入力だけを電話・法人番号に照合し、「第2営業所」などの名前から数字だけを拾って検索を広げない。名前の検索は従来どおり部分一致。PostgRESTの引用符とSQL LIKEのメタ文字を別々にエスケープし、カンマ・括弧・引用符・バックスラッシュ・%・_を含む検索を実APIで確認した。

候補のページは組織・リソース・企業条件・検索語に紐付ける。検索待ちに旧候補を選ばせず、条件変更で先頭へ戻す。検索欄の読み上げ名をcmdkのラベルにも設定した。テーブル内の活動フォームはportal経由のクリックで企業詳細へ誤遷移しないようにしている。

## 公開条件と残る制約

未公開SQLは以前の3本と今回の1本で**計4本**。新コードはこの検索ビューを使うため、既存の未公開SQLと今回のSQLを順番に適用してから公開する。今回のSQLはビュー追加だけで、業務行の削除・更新、Auth設定変更はない。以前からの認証設定/メール停止方針と本番での代表フロー確認も残る。

電話番号は数字の部分一致で、国番号+81と国内先頭0の同一視、内線番号の解釈はしない。名前のかな/全角半角/内部空白の正規化や曖昧検索も今回の対象外。検索入力中は300msの待機がある。データ件数の多い本番や同時利用時の負荷・実機Safariは未検証。番号検索は読み取り時の式評価なので、規模が拡大したら実測に基づいて索引を検討する。

先行した論理バックアップは当時の本番V1の保存であり、この未公開DB変更を含まない。長期保管先・暗号化・定期バックアップは別の残作業。
