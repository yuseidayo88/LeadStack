# 取得済み企業の詳細を再利用する検索

2026-10-07。既存V1の検索処理を継続して改善。本番未反映。

## 変更

「条件に合う企業を探す」では、外部検索の法人番号を同じ組織の保存済み候補と照合する。24時間以内に成功したgBiz詳細取得の証跡がある場合は、詳細APIを再度呼ばず、保存済みの値で現在の検索条件を判定する。初回の企業や期限切れの企業だけ詳細を取得する。

- 対象は同じ組織の行のみ。既存の組織条件付き一括読み取りとRLSを利用し、共有メモリーキャッシュは追加しない。
- 詳細APIの出典URL・法人番号・取得日時を確認する。名称／住所だけの一覧応答、出典欠落、未来日時、取得日時の不一致は再利用しない。
- 24時間は元の成功時刻から計算する。再利用による `fetched_at` / `updated_at` の更新や候補への書き込みはない。
- 手動修正・出典・電話調査結果・CRMとの関係を維持する。人数0と未掲載を区別し、毎回現在の条件で判定する。
- 画面に再利用社数と新規取得／更新社数を表示する。「取得済みの企業情報も更新する（時間がかかります）」を選ぶと、24時間以内でも詳細を再取得する。更新モードは再開情報の署名対象であり、途中で変更して同じ再開情報を使うことはできない。

## 速度と制限

取得済み20社を検索する場合、詳細20回を省略できる。最初の法人番号検索は引き続き外部APIに問い合わせるので、最新の外部検索結果に含まれた会社が対象になる。既存の「取得済み候補」の一覧絞り込みとは別の処理である。

初回検索の詳細取得速度・外部サービスの応答速度は変わらない。組織ごとの30秒間隔、1リクエスト当たり詳細5回／一覧検索2回、逐次取得、最大200社、開始後20秒で次の処理を止め25秒で中断する制限を維持する。キャッシュに当たらない企業が多い場合や、次の取得までの待機中は引き続き時間がかかる。

同じ条件で直後に再検索を押す場合も、前回開始から残っている待機時間を省略しない。外部APIの並列化、制限の緩和、課金サービスやキューの導入は行わない。

## 停止・互換性

外部API呼び出しと候補の保存には既存の永続的な実行許可／取消チェックを使う。再利用自体は読み取りだけで、詳細呼び出しの許可枠を消費しない。通信中止を検出したら読み取りループも停止し、画面は取り消された世代の応答を採用しない。基盤が通信中止を伝えない場合、次の許可チェックまで一時的に読み取り済みキャッシュの照合が進む場合があるが、新たな外部呼び出し／候補保存を許可するものではない。

旧クライアントの `refreshDetails` なしの要求と、再利用件数を含まない旧署名済みカーソルを受理する。新しいカーソルを旧実装へ切り戻して使う場合は、厳密な旧スキーマにない項目を含むため新規検索が必要。DB変更・マイグレーション・追加環境変数・依存関係の変更はない。

## 検証

専用ローカルAuth／PostgRESTとChromiumで、実際の認証・アプリ・DBを通して検証する。gBiz部分は合成応答（詳細1件120ms）で、実gBiz・公開企業サイト・本番には接続しない。初回と再検索の各1回について、クリックから最終一覧反映までを計測する。30秒の待機制限を解除せず、試行間に残った待機は別記する。本番速度の予測値ではない。
