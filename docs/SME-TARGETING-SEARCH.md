# 業務アプリ・AI連携の営業向け企業検索

既存の「企業を探す」に、中小企業向けの検索条件を追加した。企業規模や掲載された事業内容を使って候補を絞り、課題・導入意欲・予算はヒアリングで確認する。

## 操作

1. 「設備工事・保守点検」「卸売・受発注」「受託サービス」のプリセットを選ぶ。選択済みの都道府県は維持し、人数・業種・業務キーワードを設定する。
2. 従業員数の下限・上限を調整する。5〜20人、10〜50人、50〜100人のボタンも利用できる。人数未確認の企業を含める選択肢は人数指定時に適用する。
3. 新しい候補を探す場合は、都道府県と企業名の取得ヒント（設備、空調など）を設定して、Gビズの取得ボタンを押す。ヒントを選ぶだけでは外部取得を実行しない。
4. 保存済みの候補を、企業名・取得した事業内容のキーワードで絞る。複数語は空白・読点・カンマで区切り、いずれかの語に一致する候補を表示する。他の県・人数・業種・項目有無の条件とはANDで組み合わせる。
5. 候補の事業内容と出典を確認し、既存の取込確認を通じて営業リストへ追加する。検索に一致した語は営業適性や課題の確定を意味しない。

取得に使った企業名の条件だけ解除できるため、「設備」「空調」など別々に取得した候補をまとめて確認できる。検索条件・並び順は同じブラウザーの組織別に保存する。候補選択そのものは保存せず、組織切替でリセットする。保存条件は画面初期化時だけ読み込み、別タブの操作で進行中の選択を変更しない。

## 条件の意味

| プリセット         | 人数                       | 業種・キーワード                                                                                   |
| ------------------ | -------------------------- | -------------------------------------------------------------------------------------------------- |
| 設備工事・保守点検 | 10〜50人、人数未確認も含む | 設備・電気・空調・給排水・保守・点検のいずれか。保守業務は複数業種にまたがるため大分類を固定しない |
| 卸売・受発注       | 10〜50人、人数未確認も含む | 大分類I「卸売業、小売業」と業種未確認。小売も含むため詳細確認が必要                                |
| 受託サービス       | 10〜30人、人数未確認も含む | 制作・代行・支援のいずれか                                                                         |

業種不明を含む条件は、選択した業種と未確認の候補の和集合。人数は上下限を含む。0人は人数不明と区別する。「従業員数あり」を指定した場合、人数未確認は含まない。

## データとAPI

GビズAPIの `business_summary` と項目別出典を取得し、既存候補の `provenance.businessSummary` に保存する。APIは `business_summary` を表示用に返す。未掲載・詳細取得失敗では既知の説明とその出典を保持する。既存候補の説明は、取得元に掲載があれば再取得で補完できる。新しいDBテーブル・migration・有料サービスは追加しない。

事業内容はUnicodeコードポイント単位で切り詰め、出典全体が既存DBの16,000バイト制限に収まるようにする。省略した場合は詳細画面に案内と取得元リンクを表示する。手動編集で出典が増えた場合も上限を再計算する。説明文以外の情報だけで上限を超える異常データは既知の値と出典を保持し、該当候補の取得失敗として扱う。

GET `/api/organizations/{org}/company-discovery` に以下を追加。

- `employeeMin` / `employeeMax`: 任意の整数0〜2147483647。空欄は制限なし。下限>上限・小数・負数・不正な数値文字列は422。
- `includeUnknownEmployees=true`: 人数範囲内に加えてNULLを含める。人数範囲なしでは効果なし。`hasEmployees=true` はNULLを除外する。
- `includeUnknownIndustry=true`: 選択した業種に加えて空の業種配列を含める。
- `businessKeywords`: 全体200文字、8語、各語40文字まで。企業名または保存済み事業内容のいずれかに一致。

絞込み・件数計算・ページ送りはDBで行い、表示した20件だけをブラウザーで絞る実装ではない。検索文字列をPostgREST文法とパターン文法でエスケープする。`*`はPostgRESTのLIKEワイルドカードへの置換を避けるため、正規表現の全文字をリテラル化したimatchで検索する。ユーザーが任意の正規表現を実行するものではない。

## 範囲

Gビズへの検索は都道府県・企業名・法人番号で1回最大20社。細かい業務キーワード・人数・業種による全国一括取得ではない。会社名に「設備」がない設備会社など、企業名の取得ヒントだけでは見つからない企業がある。元データ未掲載の人数や事業内容は推測しない。

プリセット内の提案・ヒアリング例は営業準備のための仮説。問い合わせ送信、架電、AI利用契約・有料API呼出しは自動で実行しない。

- `npm run lint` / `npm run typecheck` / `npm run build`。

2026-10-05、上記はすべて合格。実DBでは6,000文字の日本語・絵文字を含む説明の保存上限、手動編集、1万コードポイントのASCII・絵文字混在説明の完全保持も確認した。`npm run test:discovery:browser` の既存取込・重複確認・架電記録・出典保持・閲覧者権限・組織分離・候補削除も合格。検索条件を保存する新しい仕様に合わせ、独立した既存画面テストの開始時に明示的に条件をクリアする。
