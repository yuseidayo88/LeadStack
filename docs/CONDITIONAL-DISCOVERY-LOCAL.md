# 条件から未知の企業を探す改善（ローカル検証）

基点は `fbb779d`、ローカルブランチは `fix/conditional-discovery`。既存V1を継続する。以下の初期検証後、一度公開した `715a522` は停止不具合により本番を切戻した。追加の停止修正と本番適用条件は [DISCOVERY-SCAN-CANCELLATION.md](./DISCOVERY-SCAN-CANCELLATION.md) を参照。本番の再公開は行っていない。

## 変更内容

- 会社名は任意。県・業種・従業員数・業務キーワードから明示的に検索を開始する。
- 最初の20社だけを絞る方式から、条件一致20社または走査上限200社まで、外部検索と詳細確認を続ける方式へ変更。
- 20社の条件一致が集まったら停止。「さらに20社」で同じページの未確認位置から続けられる。累計走査200社・外部ページ10まで。
- 確認件数、一致件数、従業員数・業種の未掲載件数、情報取得失敗回数を分けて表示。保存された途中結果を約2秒間隔で一覧に反映する。
- 検索開始・再開時に進捗と一覧が画面内へ入るよう表示位置を移動する。動きを減らす設定ではアニメーションを使わない。
- 停止、画面離脱、組織や検索条件の変更で実行中の通信を中止し、古い応答を無視する。全条件をまとめて入力待ちし、フォーカス移動による一覧再取得を止める。
- 一覧は240コードポイントまでの概要に限定。出典・補完情報を含む全文は候補詳細を開いたときに取得する。概要より後ろの語に一致した場合も、サーバーが一致語を返す。

## 取得条件と再開

公式[OpenAPI](https://api.info.gbiz.go.jp/hojin/v3/api-docs/v2)に基づき、県・任意の企業名・法人番号・`employee_number_from` / `employee_number_to` を外部検索へ渡す。業種・事業内容・項目有無は詳細の取得後に判定する。

従業員数未掲載も含める場合は、外部APIの人数条件を付けず、詳細で人数範囲と未掲載を判定する。未掲載を除外する場合、または「従業員数あり」の場合は人数条件を外部APIにも渡す。0人と未掲載は区別する。既知の手動修正を保持し、実際に保存された値で一致を判定する。

POST `company-discovery` の `action: scan` はNDJSONの進捗・完了・一時停止・エラーを返す。再開情報は、組織・正規化した全条件・外部ページ・そのページの法人番号配列・処理位置・件数・確認済み番号・一致IDを既存サーバートークン由来のHMACで署名する。有効期限は初回開始から2時間で、再開で延長しない。別組織・異なる条件・改ざんした再開情報は拒否する。

外部APIは逐次呼出し。1回の実行で20秒以降は次の処理を開始せず、通信・DBリクエストは25秒で中止する。既存の組織別30秒制限を維持し、時間枠で停止した場合だけ待機後に自動継続する。通信障害・429などは同じ位置を保持して手動再開を案内する。404・不正な個別詳細は失敗として記録し、未掲載の企業として採用しない。

逐次取得は[公式運用案内](https://help.info.gbiz.go.jp/hc/ja/articles/5255161447582)の検索キャッシュにある多重リクエストを控える要請を踏まえた。直接アクセスはサインインへ転送されたため、最新本文を直接確認できたとは扱わない。組織をまたぐ全サーバーでのグローバル排他制御を追加したものではない。

## 範囲と検証記録

全国の該当企業総数・完全な網羅を保証する検索ではない。走査上限と検索範囲の末尾を区別して表示する。Gビズに電話番号はないため、「電話番号あり」は保存済み電話番号がある候補が対象。今回のローカル外部連携試験には、公式APIの形式に合わせた固定の合成応答を用い、実Gビズや公開サイトへ接続しない。

新しい試験コマンドは `test:discovery:performance` と `test:discovery:scan`。後者は専用の明示的オプトインpreloadで合成Gビズ応答だけを返し、Supabase以外の外部通信を拒否する。fixture以外のDBやアカウントへ向けない。
